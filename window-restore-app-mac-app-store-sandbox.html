Why window restore apps are not on the Mac App Store

16 November 2026 · Martín Acuña Lledó · Applies to macOS 13 Ventura through macOS 27

If you look for an app that puts your windows back after sleep, you will notice most of them are sold on their own websites, not in the Mac App Store. People ask why, and whether that makes them less trustworthy. The short answer is a rule, not a choice: the Mac App Store requires the sandbox, and the sandbox blocks the one API these apps need. This page shows what Apple's own documents and engineers say, why a few older apps are still in the store, the one workaround a developer has found, and how to check any app on your Mac.

The rule

Two Apple documents meet here.

  • The store requires the sandbox. App Review Guideline 2.4.5 says apps distributed via the Mac App Store "must be appropriately sandboxed".
  • The sandbox forbids Accessibility control. Apple's documentation "Protecting user data with App Sandbox" has a section called "Review functionality that is incompatible with App Sandbox". Its list of restricted activities includes "Use of accessibility APIs in assistive apps", along with sending Apple Events to arbitrary apps and terminating other running apps.

Moving and resizing another app's windows is done through the Accessibility API. That is why window managers, Many Displays included, ask you to allow it in System Settings → Privacy & Security → Accessibility. An app that needs that permission cannot be sandboxed, so it cannot go through the store.

What Apple's engineers say

Developers keep asking on Apple's developer forums, and the answer has not changed.

  • October 2025. A developer's window manager was rejected for "App sandbox not enabled". Quinn "The Eskimo!", an engineer in Apple's Developer Technical Support, answered: "It's not possible to use the Accessibility APIs from a sandboxed app", and "your only path forward here is to directly distribute your app using Developer ID signing."
  • December 2025. Another developer reported that with the sandbox on, the Accessibility prompt never appears and the app cannot even be added by hand in System Settings. The same engineer replied by pointing to the answer above.
  • July 2026. A third developer asked about an exception for window managers. The reply: Developer Technical Support does not speak for App Review, but "our documentation makes it clear that the Accessibility APIs are not supported in sandboxed apps."

Why some older apps are still there

You can still find a few window tools in the Mac App Store. The explanation from developers who went through it is that apps already in the store before the sandbox became mandatory were allowed to stay, with limits:

  • Many Tricks, in its FAQ on why Witch 4 is not in the Mac App Store, says Witch cannot be sandboxed because it works with other apps through the Accessibility API, and that existing apps could keep receiving bug fixes but not new features. It quotes Apple's documentation: "you cannot sandbox an app that controls another app."
  • PopClip left the Mac App Store in March 2024. Its developer, Nick Moore, wrote that he could not update it with new features there "due to Apple's sandboxing policy", and that App Review would accept an update without the new features.

So an older window app in the store is not proof the rule bends. It is an app that was there first and is limited in how it can change. Stay is one of them: my research notes from October record that the Mac App Store copy of Stay 1.5.1 had no sandbox entitlement.

The one workaround

In July 2026 developer Blake Crosley described shipping a sandboxed window tiler in the store by not moving windows itself. The app works out where each window should go and hands that plan to a Shortcut the user installs, and Shortcuts does the moving with its Find Windows, Move Window and Resize Window actions. He lists the trade-offs: the user has to install the companion Shortcut and accept an automation prompt, and the store build cannot use Accessibility notifications, so it polls the window list instead. I have not tested that app. It shows the store route is possible for tiling, with real limits, and it was not built to restore windows after sleep.

Check any app yourself

Two Terminal commands tell you where an app comes from and whether it is sandboxed. Replace the path with the app you want to check:

spctl -a -vv /Applications/AppName.app

The source= line says Mac App Store for store apps and Notarized Developer ID for apps sold directly and notarized by Apple. If it is rejected or says neither, be careful.

codesign -d --entitlements - /Applications/AppName.app

If the output contains com.apple.security.app-sandbox, the app is sandboxed. A window manager that is notarized and not sandboxed is normal: it is the only way it can work.

Notarization means Apple scanned the app for malware before it could run without warnings. It is not a review of what the app does. Whatever the source, the Accessibility permission lets an app control other apps, so grant it only to apps you trust, and remove it in System Settings when you stop using one.

How Many Displays handles it

Many Displays is sold directly at manydisplays.com, signed with Developer ID and notarized by Apple, for the reasons above. It needs the Accessibility permission to move windows. On first launch a welcome window explains why before macOS asks, and without it the app still saves positions but cannot move anything, and says so in the menu.

Two things try to make up for not having the store's review:

  • The source is on GitHub under the Functional Source License, so anyone can read what it does with that permission, or build it themselves.
  • No network access and no analytics. It only talks to Apple's update server when you check for updates or have automatic checks on.

Where this does not help you:

  • No store purchase. There is no Family Sharing and no App Store refund flow. Licences are bought through the site's checkout after a 14-day trial with no account, and updates come through the app instead of the store.

Questions

Why isn't there a window restore app on the Mac App Store?

Apps on the Mac App Store must be sandboxed, under App Review Guideline 2.4.5. Moving another app's windows needs the Accessibility API, and Apple's App Sandbox documentation lists use of accessibility APIs in assistive apps as forbidden in a sandbox. An Apple engineer on the developer forums says the only path for such an app is direct distribution with Developer ID.

Then why are some window apps still on the Mac App Store?

Apps that were already in the store before sandboxing became required could stay. Developers of Witch and PopClip describe the deal: bug fixes are accepted without sandboxing, new features are not. That is why some long-standing listings remain while new window managers are rejected.

Is an app from outside the Mac App Store safe?

Check that it is notarized. Run spctl -a -vv on the app in Terminal: a notarized app shows source=Notarized Developer ID. Notarization means Apple scanned it for malware. It is not a review of what the app does, so the Accessibility permission you grant still matters.

Is there any way to move windows from a sandboxed app?

One developer describes a workaround: the sandboxed app works out where windows should go and asks a Shortcut you install to move them, using the Shortcuts window actions. It needs that companion Shortcut and an automation permission, and it cannot use Accessibility notifications.
